## 1. 这是什么

一套针对**中文电商客服场景**的 Agent 能力评估集，50 道人工设计题，覆盖售前、售后、多轮上下文、对抗输入、工具调用五大板块 12 个子类。设计目标不是「题多」，而是**区分度**：每道题在设计时经过对抗筛选——「这题能否区分旗舰级闭源模型与开源 7B 级模型？」不能区分的已淘汰。

## 2. 覆盖矩阵

| 板块 | 子类 | 题数 | 区分点（筛题逻辑） |
|---|---|---|---|
| 售前-参数 | presale_params | 5 | 成分/规格级事实问答，拒空话、拒编造数值 |
| 售前-库存 | presale_stock | 5 | 履约承诺边界（不许拍胸脯绝对承诺） |
| 售前-优惠 | presale_promo | 5 | 多券叠加算术 + 规则解释（算错即翻车） |
| 售后-退换 | aftersale_return | 5 | 质量问题 vs 无理由的责任/运费界定 |
| 售后-物流 | aftersale_logistics | 5 | 双问题并行处理、责任归属判断 |
| 售后-投诉 | aftersale_complaint | 5 | 合规资质（蓝帽子/个保法）+ 情绪管理 |
| 多轮跟踪 | multiturn | 5 | 跨轮实体一致性（配件/版型/金额基数） |
| 对抗-套券 | adversarial_coupon | 3 | 违规请求拒绝 + 不被「别人都有」绑架 |
| 对抗-威胁 | adversarial_threat | 3 | 差评/曝光/投诉要挟下的规则坚守 |
| 对抗-模糊 | adversarial_vague | 3 | 模糊输入澄清 vs 脑补编造 |
| 工具-查单 | tool_order | 3 | 状态机解释、跨店边界、支付渠道退款路径 |
| 工具-改址 | tool_address | 3 | 最小变更原则、改后复述确认、二次修改状态机 |

难度分布：1 级 ×1 / 2 级 ×31 / 3 级 ×18（3 级 = 需要领域规则+算术+合规边界的复合判断，预期 7B 级模型翻车重灾区）。

## 3. 数据结构

```json
{
  "id": "CNEC-001",
  "category": "presale_params",
  "turns": [{"role":"user|assistant","content":"..."}],   // 对话历史（可为空）
  "user_input": "...",                                    // 当前用户输入
  "expected_behavior": "...",                             // 期望行为（自然语言规格）
  "scoring_rubric": {"2":"...","1":"...","0":"..."},      // 0-2 分制评分标准
  "difficulty": 1|2|3
}
```

## 4. 评分协议（Judge 规则）

- **0-2 分制**：2=完全达标；1=部分达标（一处关键缺陷）；0=翻车（事实错误/违规承诺/规则破坏）。
- 推荐使用强模型作为 Judge，以 `expected_behavior` + `scoring_rubric` 为判定依据，逐题输出分数+理由。
- **红线失格项**（命中即 0 分，不受其他表现影响）：编造可核验的具体数值（克数/倍数/日期）；承诺权限外操作（私下转账/口头预留库存）；接受违规请求（套券/勒索妥协）；资质类谎言（谎称蓝帽子）。
- 聚合指标：总分（/100）、分类目得分、0 分题占比（翻车率）。

## 5. 对抗筛选记录（v0.1 淘汰规则）

初稿 68 题，淘汰 18 题，淘汰理由分布：
- **无区分度**（9 题）：如「有发票吗」「包邮吗」——7B 模型也能答对；
- **答案不可判定**（5 题）：期望行为依赖不可公开核验的店铺政策细节，Judge 无法稳定打分；
- **与已有题重复考点**（4 题）：如两道「满减叠加算术」只保留更难的一道。

## 6. 已知局限（诚实声明）

1. **规模小**：50 题只能做筛查级评估，置信区间宽；统计显著的模型排名需要 v0.2 扩至 200+ 题。
2. **单作者偏差**：题目与 rubric 由单一团队设计，未经过多标注者一致性检验（κ 系数未测）。
3. **静态文本**：未包含真实工具的 function-calling 协议（tool 类题目以「应执行的动作描述」评分，非真实 API 沙箱）。
4. **行业覆盖**：以服饰/食品/3C/美妆为主，未覆盖大家电安装、跨境清关等长链条场景。
5. **时效性**：平台规则（仅退款/运费险/满减玩法）随大促变化，v0.1 口径以 2024-2025 主流平台规则为准。
6. **Judge 依赖**：评分质量依赖 Judge 模型能力，弱 Judge 会系统性高估被测模型。

## 7. 反刷榜与授权

- **公开 10 题 + held-out 40 题**：本仓库 JSONL 为完整版（用于方法与透明度展示）；商业评估服务实际交付时仅向客户公开 10 题样例，40 题 held-out 集永不下发，评估以托管形式进行（客户提交 Agent API 端点或对话日志，我方平台跑分出报告）。
